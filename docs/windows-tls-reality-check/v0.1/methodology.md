# Methodology and selection of measurements

The frozen primary matrix covers six client applications × two states (A/B) × two server profiles, with three S1 repetitions and one S2 repetition per client/state: **48 planned runs**. A later State A browser-version supplement adds three S1 repetitions and one S2 run for each of Edge, Chrome and Firefox: **12 additional runs**.

## Selection rules

- A/S1 original: attempt `a01`, repetitions `r01..r03` for all six clients.
- A/S2 original: attempt `a01` for curl/ps51/ps77 and `a03` for Edge/Chrome/Firefox, `r01` only.
- B/S1 original: attempt `a04` for curl `r01` (prior attempts retained); `a01` otherwise for all clients and all three repetitions.
- B/S2 original: attempt `a01`, `r01` for all six clients.
- Supplemental A/S1: attempt `a02`, repetitions `r01..r03` for the three browsers.
- Supplemental A/S2: attempt `a04`, `r01` for the three browsers.

The source retained 69 attempt-metadata records and 67 captures. Two early A/S2 browser attempt directories had metadata but no capture; seven other unselected attempts had captures. These are **retained outside the accepted 60-run dataset**, not deleted or silently rewritten.

## Local validation performed

- `sha256sum -c` verified the 67 existing capture/artefact pairs with zero recorded failures.
- Selected-run metadata and two checksum files for each of 60 accepted cases were checked, with zero errors.
- TShark-derived ClientHello/ServerHello group fields were compared against expected behavior **on a per-TCP-stream basis** in the preliminary offline audit: 60 PASS / 0 REVIEW.
- In the three expected failures the TCP streams showed ClientHello, no final ServerHello and TLS alert 40.

The captured HTTP status is reported by the operator, and the private metadata is contemporaneous local evidence; this is not a separately signed application-layer trace. No new Windows measurements were generated by the publication step.

## Public validation scope

The GitHub runner has only [results.csv](results.csv) and source code. It can detect incomplete, duplicated, corrupted-format or internally inconsistent published records, but **cannot verify a private packet capture from its hash alone**. Additional TLS semantics, certificate-chain evaluation and packet-level validation require the original captures.
